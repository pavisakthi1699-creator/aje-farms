## Affected Pages and Routes

- `/search` — verify cached search keeps its existing result order, scopes, saved-document boost, and offline status while reusing a generation-safe index.
- Account sign-out/access transition — verify protected course, lesson, and document records are inaccessible immediately after the cache is cleared.

## Key Interactions to Verify

- First offline query builds the normalized base index.
- Later queries at the same content generation reuse the base index.
- A successful catalog refresh advances the generation and rebuilds on the next query.
- Refresh cancellation uses a separate request token so publishing a new content generation cannot skip refresh cleanup.
- Current-session community posts are searchable without rebuilding the repository-backed base index.
- A session-local community post with an ID already present in the cached feed is ignored so the cached/server copy remains authoritative without duplicating the result.
- Saved-document search retains the existing document-only boost.
- Returning from a search destination does not change cached search behavior.

## Edge Cases

- Shared JavaScript/Dart normalization fixtures: punctuation, whitespace, compatibility forms, composed/decomposed diacritics, non-BMP letters, and 119/120/121-code-point boundaries.
- Empty repositories and zero-match queries.
- More matches than the 50-result cap, with deterministic top-K ordering and `truncated=true`.
- Limits 1, 20, and 50; a score tie at the cutoff; and a saved document promoted across the cutoff.
- Failed refresh after unlocked content was cached.
- Account clear while a catalog refresh is in flight.
- Local community posts changing while the base catalog generation is unchanged.

## Critical Paths

- Refresh unlocked catalog → search protected content → clear account cache → repeat query → no prior protected result appears.
- Build large representative cache → measure cold index creation separately → warm index → run reviewed query corpus → report warm p50/p95 without a flaky CI wall-clock assertion or including corpus construction.
- Run the same normalization fixture through server JavaScript and Flutter Dart and require identical outputs.
